# 명세서 구현분 적용 메모

`RESCENE_SWAP_SPEC.md` 1번에 따라 구현 단계에서는 테스트, 브라우저 실행, 미리보기, 스크린샷, 서버 SQL 실행, 배포를 하지 않습니다. 사용자의 별도 요청 후 통합 검증과 오류 수정을 진행하고 최종 배포를 한 번 진행합니다.

## 서버 변경

`migrations/003_spec.sql`은 001(schema.sql), 002 이후 한 번 적용할 추가 마이그레이션입니다. 새 프런트엔드는 poca3 RPC를 사용하므로 서버 변경과 함께 반영해야 합니다. 사용자의 배포 요청에 따라 운영 서버에 적용했습니다.

- 닉네임과 bcrypt 해시로 저장한 4자리 PIN을 사용합니다. PIN은 브라우저 저장소나 조회 RPC에 저장·노출하지 않습니다.
- PIN을 5번 틀리면 닉네임 및 기기 세션 기준 15분 제한합니다. 로그인 세션은 30일 유지됩니다.
- 기존 사용자는 기존 브라우저에서 같은 닉네임으로 ‘처음 이용 · PIN 등록’을 하면 기존 등록정보와 내역을 연결합니다. 다른 기기는 등록한 닉네임/PIN으로 로그인합니다. PIN 설정 전 삭제된 익명 세션은 자동으로 복구할 수 없습니다.
- 관리자가 등록한 공용 도감만 사용합니다. 일반 사용자의 도감 등록 RPC와 사진 업로드를 서버에서 차단합니다.
- 보유 포카마다 특정 도감 ID들, 멤버 조건, 아무거나 가능을 저장합니다. 조건은 OR이며 양쪽 모두 일치하면 맞교환, 한쪽만 일치하면 일반 후보입니다.
- 교환번호는 사용자별 고유 번호이며 재로그인 후에도 동일합니다.
- 약속 요청 시 양쪽 1장을 예약하고 상대가 수락합니다. 요청부터 15분이 지나면 자동 해제합니다. 만료시간이 지난 예약은 가용수량에서 즉시 제외하고 다음 서버 조회/동작에서 취소 상태를 정리합니다. 화면은 실시간 알림 및 기존 15초 조회로 갱신합니다.
- 약속 후 한쪽이 완료를 요청하고 다른 쪽이 확인하면 양쪽 보유수량만 1장 차감합니다. 다른 후보 조건은 유지합니다. 수정/나가기는 관련 약속을 취소합니다.
- 이전 버전의 완료 내역은 유지합니다. 이전의 여러 장 단위 미완료 요청은 새 1장 약속으로 다시 요청하도록 취소합니다.
- 로그인 복구한 사용자에게는 자신의 과거 거래 사진 읽기도 허용합니다.

## 관리자 지정

최초 관리자는 사용자에게 계정 닉네임을 확인한 후 서버 운영자가 아래 형태로 지정합니다. 임의의 사용자를 자동 승격하거나 클라이언트에서 관리자 권한을 설정하지 않습니다.

```sql
insert into public.poca3_admins(owner)
select owner from public.poca3_accounts
where public.poca_name(nickname)=public.poca_name('확인된 관리자 닉네임')
on conflict do nothing;
```

관리자가 로그인하면 기존 도감 추가 버튼이 나타납니다. 행사·종류·사진과 멤버 복수 선택 또는 단체를 지정합니다. 일반 사용자는 사진을 눌러 선택하기만 합니다.

## 구현 상태

로그인, 공용 도감 권한, 멤버·유닛 버튼, 포카별 후보, 1장 약속 교환, 재로그인 내역, 여기 있어요 색상·번호 표시 코드를 작성했습니다. 사용자 배포 요청 후 통합 검사에서 SQL 오류 두 곳을 수정했습니다. tests/spec.test.js 및 갱신한 브라우저 검사에서 PIN 복구, 권한, 약속·완료·만료와 모바일 화면을 확인했습니다. 실제 Supabase에서도 PIN 로그인, 두 사용자 교환과 다른 기기 복구를 확인했습니다. 관리자 지정은 운영자 닉네임 확인 후 진행합니다.
